# 오렌지톡 설문 릴레이 모듈

설문 작성·저장은 교사용 앱에서 수행하고, 인터넷 응답은 기존 키오스크 릴레이 서버에 이 모듈을 추가해 수집합니다. 학교와 가정에서 같은 HTTPS 링크를 사용합니다. 교사용 앱이 꺼져 있어도 서버는 응답을 받습니다.

이 저장소에는 운영 중인 `relay.school114.org`의 서버 소스와 배포 설정이 없습니다. 따라서 운영 서버에 설치되었다고 간주하면 안 됩니다. 앱은 서버 게시 성공을 확인해야만 실제 링크와 QR을 표시합니다. 미설치 서버의 오류가 나더라도 설문은 로컬에 저장됩니다.

## 기존 서버에 연결

1. `node scripts/package-survey-relay.cjs`로 필요한 소스만 묶습니다. 출력 디렉터리는 `_preview/survey-relay-bundle`입니다. 실제 학생 데이터나 인증정보는 포함하지 않습니다.
2. 해당 디렉터리의 `survey-server`와 `src/shared/survey-model.js`를 상대 경로 그대로 릴레이 서버에 복사합니다. Node.js 18 이상과 Express가 필요합니다. 앱의 SQLite DB를 운영 릴레이에 복사하지 않습니다.
3. 서버의 기존 학교 채널·보건교사 토큰 검증 함수를 연결합니다. 아래 `verifyExistingNurseToken`은 예시 이름이며 운영 서버의 실제 인증 함수로 바꿔야 합니다. 공개 키오스크 접속키를 교사 토큰 대신 허용하면 안 됩니다.

```js
const { createSurveyRouter } = require('./survey-server/router');
app.use(createSurveyRouter({
  dataDir: '/var/lib/orangetalk/surveys',
  authenticate: async (channelId, bearerToken) => {
    return verifyExistingNurseToken(channelId, bearerToken);
  }
}));
```

이 라우터는 catch-all 404 처리와 정적 앱 라우팅 앞에 등록합니다. 기존 JSON 파서가 1MB 미만을 제한한다면 라우터를 그 파서 앞에 둡니다. 공개 설문 요청에는 기존 교사용 로그인 미들웨어를 적용하지 않으며, 관리 API는 이 모듈의 `authenticate`가 검증합니다. 프록시는 아래 경로를 같은 서버로 전달해야 합니다.

- `/s/:id`, `/s/assets/*`: 휴대폰 응답 화면
- `/api/v1/surveys/public/:id`: 정의 조회 및 응답 제출
- `/api/v1/surveys/channels/:channel/forms/:form`: 교사 전용 게시·수집·마감

운영 외부 주소는 HTTPS를 사용합니다. 프록시 환경의 Express `trust proxy`는 실제 프록시 구성에 맞게 설정해야 IP별 요청 제한이 올바르게 동작합니다. 공개 API는 학교 공용 IP를 고려해 IP당 분당 600회(조회·제출 합계)를 허용합니다. 토큰과 응답 본문을 웹 서버 로그에 기록하지 않습니다.

## 저장과 재시도

- 서버 데이터는 웹 정적 디렉터리 밖에 저장합니다. 정의와 응답은 파일을 임시 파일로 쓴 뒤 교체합니다.
- 현재 파일 저장소는 **단일 Node 프로세스/단일 작성자** 기준입니다. PM2 cluster나 여러 인스턴스로 같은 디렉터리를 쓰지 않습니다. 여러 프로세스가 필요한 운영 환경에서는 트랜잭션 가능한 DB 저장소로 교체한 후 배포해야 합니다.
- 공개 응답 화면에는 학교 학생 명단이나 교사 토큰을 전달하지 않습니다. 학년·반·번호·이름을 입력하며 앱이 선택한 대상 명단과 일치 여부를 확인합니다. 일치하지 않는 응답은 버리지 않고 `명단 확인 필요`로 보관합니다.
- 설문 링크는 응답용이며, 응답 조회 API는 학교 채널의 교사 인증을 요구합니다.
- 제출 ID로 네트워크 재시도에 따른 중복을 막습니다. 서버 응답을 앱 DB에 저장한 다음 수신 확인(ack)을 보내 서버의 해당 응답 본문을 지웁니다. 앱에서는 기존 학년도·설문·학생 식별자 기반 upsert를 사용합니다.
- 응답을 받은 설문은 정의를 변경할 수 없습니다. 수정이 필요하면 현재/과거 설문의 `복사`로 새 설문을 만듭니다. 수집 전 수정도 새 버전을 부여하여 이전 화면의 제출을 차단합니다.
- 기간과 마감 시간은 한국 표준시 기준입니다. 마감 후에도 교사는 남아 있는 응답을 가져올 수 있습니다.
- 응답 화면에는 답변을 브라우저 영구 저장소에 남기지 않습니다. 현재 탭의 재시도용 무작위 ID와 제출 완료 여부만 sessionStorage에 보관합니다. 제출 후 새로고침해도 완료 화면을 유지하며, 공용 기기의 다음 학생은 `다른 학생 응답하기`로 새 제출 ID를 발급받습니다.

## 앱에서 사용

1. 매직 스테이션 → 설문 템플릿과 활용 → 새 설문 만들기.
2. 대상·언어·문항을 설정한 뒤 미리보기에서 `이 PC에 저장` 또는 `온라인 게시 · QR/링크 만들기`를 선택합니다.
3. 온라인 게시는 환경설정의 기존 학교 키오스크 릴레이 주소·채널·교사 토큰을 사용합니다.
4. 현재/과거 설문에서 링크 복사, 응답 가져오기, 마감, 복사를 할 수 있습니다. 통계를 열 때도 새 응답을 가져옵니다.
5. 정상적인 HTTPS 휴대폰 접속, 교사 인증 실패 시 거절, 응답 저장·수집·마감을 운영 서버에서 확인한 뒤 배포를 완료합니다.

## 검증

`npm run test:survey`는 가상 학생 자료와 임시 로컬 서버만 사용합니다. 운영 서버나 실제 학생 DB에 연결하지 않습니다. 기본 건강조사, 13종 문항, 분기 검증, 학교 간 권한 분리, 서버 재시작, 제출 재시도, 로컬 저장 실패, 수신 확인 후 서버 응답 삭제, 마감, 실제 Electron 편집기와 모바일 크기 응답 화면을 확인합니다. 화면 캡처는 `_preview/survey-ui`에 생성됩니다.

`npm run test:magic`은 위 테스트와 화면 라우팅 회귀 검사를 함께 실행합니다. 지연된 저장·게시 중 화면 이동, 번역·분기 보존, 공용 기기의 다음 학생 응답, 학교 공용 IP의 125명 병렬 응답 및 페이지별 수집, 연수 등록부·이수 현황·안내문 편집도 포함합니다. 연수 내보내기는 표 데이터와 인쇄 HTML까지 확인하며 실제 프린터·Google Sheets 전송은 수행하지 않습니다.

`npm run test:magic:layout`은 실제 학교용 스타일·상단 메뉴·레이아웃 코드를 포함한 격리 Electron 창에서 반응형 화면만 검사합니다. 교사용 13개 화면을 창 크기·배율 13조합(390~1920px, 100·125·150·200%)으로 연속 변경하고, 응답 화면은 320~844px의 6개 해상도에서 확인합니다. 총 181개 상태에서 화면 넘침, 스크롤로도 접근할 수 없는 버튼, 다른 요소에 가려진 입력란, 미리보기 잘림을 검사하고 크기 변경 전후 입력값을 비교합니다. 결과와 캡처는 `_preview/magic-responsive/responsive-report.json` 및 같은 디렉터리에 저장됩니다. 큰 설문 표와 모바일 표 문항은 내부 가로 스크롤을 허용하되 모든 입력·관리 버튼에 접근할 수 있어야 합니다. 실제 휴대폰 운영체제·소프트 키보드 검증을 대체하지는 않습니다.
